Most projects need no configuration: Forge activates packs from your manifests and lock files. Two optional inputs adjust the result. Forge never rewrites them, and Claude must ask before editing them.

## `forge.yaml`

```yaml
forge: "0.5"
packs:
  add: [typescript/zod]           # activate a pack (and its ancestors)
  remove: [typescript/playwright] # deactivate a pack and its sub-packs
disable:
  - id: python/pytest/run
    reason: The suite needs a GPU; it runs in CI only.
accept:                           # a config change the ratchet reported, made on purpose
  - rule: typescript/config-ratchet
    change: "biome.json: linter.rules.suspicious.noExplicitAny error -> warn"
    reason: Migrating the legacy API client; back to error by Q3.
```

Every rule blocks, so a rule you don't want is disabled with a reason.

`accept` answers the config ratchet (`python/config-ratchet`, `typescript/config-ratchet`): when a tool config is loosened (a lint rule lowered, a strict flag removed, a path excluded, a coverage threshold lowered, `--passWithNoTests` added), `check.sh` fails at Stop, at pre-commit and in CI with one line per setting. Copying that line into `accept` with a reason records the change as deliberate; once it is committed, the ratchet measures against the new config. The file format is in [Schemas](../../reference/schemas/#forge).

## Project-local rules

Rule files in `.forge/rules/` use the same format as pack rules. A local rule whose `id` equals a pack rule's id replaces it; a new id adds a rule. `forge test`, run inside the repository, tests their examples too.

Rules have no parameters; a local rule of the same id is how you adapt one. For example, to exempt a public route from `typescript/nextjs/route-handler-auth`, or to add your own auth helper or wrapper's name, copy the rule from its [pack page](../../packs/typescript/nextjs/) into `.forge/rules/route-handler-auth.yaml` and add `"!app/api/newsletter/route.ts"` to `scope.files`, or the name to the regex. The same goes for the helper lists of `server-action-auth`, `route-handler-validate`, `typescript/no-ssrf` and `python/no-ssrf`.
