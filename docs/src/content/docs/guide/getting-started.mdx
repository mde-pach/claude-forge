You need Claude Code **≥ 2.1.295** and `git`. Forge itself needs no Python, Node or Bun; the tools it pins (uv, ty, zizmor, hadolint, …) are downloaded into its cache, each checked against its sha256.

## Install

Any one of:

```sh
curl -LsSf https://github.com/mde-pach/claude-forge/releases/latest/download/install.sh | sh
uv tool install claude-forge
npm install -g @maximedepachtere/claude-forge
cargo install --locked --git https://github.com/mde-pach/claude-forge forge-cli
```

The binary is installed as both `claude-forge` and `forge`. The hook entries call `claude-forge`, so a Foundry `forge` on your PATH never runs in their place. The installed binary is a launcher: in a repository it runs the version `forge.lock` records, downloading it into the cache at `forge apply` or session start when needed.

## Once per machine

```sh
forge apply --user
```

Forge shows what it appends to `~/.claude/settings.json` and asks before writing. See [User level](../user-level/).

## In each repository

```sh
cd my-app
forge apply
git add forge.lock .claude && git commit -m "Add Forge"
```

Forge detects your stack, writes `.claude/rules/forge-*.md` and the hook entries in `.claude/settings.json` (asking first), records it all in `forge.lock`, and audits your tool configs. Commit the result: everyone who clones the repository gets the same setup. A clone without Forge installed sees one message at session start saying the checks are off and how to install it; every other hook does nothing.

- **Questions.** `forge apply` asks before changing a shared settings file and before creating a pre-commit hook. `--yes` answers yes to both; without a terminal and without `--yes`, a settings change stops apply with a message. `--yes` never edits a hook manager's config (a file your team tracks); `--pre-commit` does.
- **The pre-commit hook.** Without a hook manager Forge creates `.git/hooks/pre-commit`, which runs `claude-forge check --changed`. With one (pre-commit, lefthook, Husky, `core.hooksPath`), it adds a marked block to its config, which `forge remove` takes out. A repository's own existing hook is never touched: add `claude-forge check --changed` to it. `forge status` says whether commits are checked.
- **A repository you don't own.** `forge apply --local` keeps the settings entries in `.claude/settings.local.json`.
- **An old layout.** A repository set up by the TypeScript Forge (0.5: `.forge/check.sh`, `.claude/skills/forge-project/`, `.forge/forge.lock.json`) is migrated by `forge apply`: it lists what it deletes and asks first.

## A new project

`forge init` creates the stack's missing tool configs from the packs' templates (`ruff.toml`, `ty.toml`, `biome.json`, `tsconfig.json`), then applies.
