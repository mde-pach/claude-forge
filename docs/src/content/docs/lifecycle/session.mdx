## Session start

At startup, resume, `/clear` and `/compact`, `claude-forge hook session-start` puts Forge's uv on Claude's PATH (through `CLAUDE_ENV_FILE`), downloads the locked Forge version and tools when they are missing, and starts the types engine in the background. Claude Code loads each active pack's context from `.claude/rules/forge-<pack>.md`.

## Tool call

Before a tool runs, Claude Code applies the permissions Forge appended (`deny` refuses, `ask` asks you) and, at user level, runs Bash in the sandbox. For Bash commands, `claude-forge hook pre-tool-use` parses the command line into simple commands (following `sh -c`, `eval`, `env -S`, `find -exec`, `xargs`, `cd`) and matches the guard rules structurally: quoted arguments and heredoc bodies are data, so `git commit -m "remove chmod 777"` is not a `chmod`. A refusal reaches Claude with a neutral reason.

The same hook refuses reads and edits of Forge's cache and state, which nothing points Claude to.

### When nobody can answer an ask

In an autonomous run (`claude -p`, the Agent SDK, the GitHub Action) nobody is there to answer an ask, and Claude Code denies it unseen. Forge sends the ask to an **independent reviewer** instead: a fresh `claude -p` that sees only the action and the turn's request, may read the repository, and runs without hooks, MCP servers or the agent's conversation. A rule that asks can carry the one question the reviewer answers (`review:`). Every verdict is logged in the repository's state directory.

| `FORGE_ASK_REVIEW` | Reviews asks |
|---|---|
| `auto` (default) | when nobody can answer (an SDK or GitHub Action entrypoint) |
| `always` | in every session, e.g. a remote session you leave running |
| `never` | never: asks are denied, as in plain Claude Code |

In `dontAsk` mode asks stay denied. `FORGE_REVIEW_MODEL` picks the reviewer's model.

### Edits to existing tests

An Edit or Write that changes what a test asserts, or removes it, when the test existed at the start of the turn, asks first: the change is right when the task changes the behaviour the test asserts, and wrong when it only makes failing code pass. In an autonomous run the reviewer answers, given the turn's request. New tests do not ask. A change nobody approved (made through Bash, say) blocks Stop.

## After an edit

After an `Edit` or `Write` (or a Bash command that changes files), `claude-forge hook post-tool-use` formats the file with the formatter your project chose, applies safe fixes, lints it and runs the `forbid` rules on its changed lines; findings go back to Claude as `path:line description`. Forge never formats or lints style with a tool the project has not chosen. The type check runs in the background (`asyncRewake`), answered by the types engine (ty for Python, the project's TypeScript), and wakes Claude when a changed file has errors. `FORGE_EDIT_TYPECHECK=always` or `never` overrides when it runs after edits.

### Files changed by Bash

Agents often edit through Bash (a heredoc, `sed -i`, `git apply`). Before each Bash command the PreToolUse hook snapshots the working tree as a git tree (your index and object store are never touched); afterwards the same checks run on every file the command added or modified, up to 20, also when the command failed partway (PostToolUseFailure). A tree too large to snapshot within `FORGE_SNAPSHOT_TIMEOUT` seconds (default 3) is left to the Stop check. Worktrees under `.claude/worktrees/` and gitignored trees are not snapshotted.
