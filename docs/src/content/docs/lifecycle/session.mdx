## Session start

At startup, resume, `/clear` and `/compact`, `session-start.sh` prints a short summary for Claude. Claude Code also loads each active pack's context from `.claude/rules/forge-<pack>.md`.

## Tool call

Before a tool runs, Claude Code applies the permissions Forge appended (`deny` refuses, `ask` asks you) and runs Bash in the sandbox at user level. For Bash commands that a permission prefix cannot express, the PreToolUse guard matches `guard.rules` patterns. Permissions and the sandbox are the protection boundary; the guard is a tripwire.

### When nobody can answer an ask

In an autonomous run (`claude -p`, the Agent SDK, the GitHub Action) nobody is there to answer an ask, and Claude Code denies it without anyone looking at it. Forge sends the ask to an **independent reviewer** instead: a fresh `claude -p` that sees only the action (the tool, its input, the Forge rule that asked, the repository path), may read the repository, and runs without hooks, MCP servers, settings or the agent's conversation. It allows or denies as a careful developer seeing only that action would, so the decision is not made in the agent's rush. Every review is logged in `.forge/state/reviews.log` (or `~/.claude/forge-reviews.log`).

It covers both kinds of ask: a guard rule's `ask` (in `guard.sh`) and any permission prompt (a `PermissionRequest` hook, `review.sh`; the project-level one defers to the user-level one). It only acts when nobody can answer: in an interactive session, the usual prompt appears.

| `FORGE_ASK_REVIEW` | Reviews asks |
|---|---|
| `auto` (default) | when `CLAUDE_CODE_ENTRYPOINT` is `sdk-cli`, `sdk-ts`, `sdk-py` or `claude-code-github-action` |
| `always` | in every session, e.g. a cloud or remote session you leave running |
| `never` | never: asks are denied, as in plain Claude Code |

In `dontAsk` mode asks stay denied (you chose that). `FORGE_REVIEW_MODEL` picks the reviewer's model. In a headless run, Claude Code loads the project's Forge plugin only when the workspace is trusted (accept the trust dialog once, interactively).

### Edits to existing tests

An Edit or Write that changes a test (anything in it, formatting aside: its assertions, but also its input data, `.each` table or an early `return`), or removes it, when the test existed at the start of the turn, asks first: the change is right when the task changes the behaviour the test asserts, and wrong when it only makes failing code pass. In an autonomous run an independent reviewer answers, given your request for the turn. New tests do not ask. An edit that ran was approved; a change nobody approved (made through Bash, say) is blocked at Stop. A changed fake, fixture or helper in a test file (or `conftest.py`) is reported once at Stop: test doubles encode the interface callers rely on, so production usually keeps it (a property alias for a moved attribute).

## After an edit

After an `Edit` or `Write` (or a Bash command that changes files, below), `post-edit.sh` formats the file silently, lints it and runs the ast-grep `forbid` rules on it; findings go back to Claude as context. `typecheck.sh` runs the project type check in the background and wakes Claude when it fails. Claude Code runs it in the background only in an interactive session or with streaming input (the Agent SDK, `--input-format stream-json`); under `claude -p "<prompt>"` it would wait for it after every edit (32 to 64 s per edit in a large TypeScript repository), so there `typecheck.sh` steps aside and the Stop check runs the type check once per turn. `FORGE_EDIT_TYPECHECK=always` runs it after every edit anyway; `never` never does. tsc runs incrementally, with its build info in `.forge/state/`.

<Spec file="08-project-hooks" describe="PostToolUse" />

Before the lint report, a lint check's safe fixes run (`fix_run`): sorted imports and pyupgrade with ruff, when your config selects them, and Biome's safe fixes. Unused imports are never removed, since an import added now is often used in the next edit. When a fix changes the file, Claude is told in one line, so it re-reads the file before editing it again. Biome applies its safe fixes in the lint run itself (`biome check --write`), so it runs once per edit; Claude is told when that run changed more than the formatting. Each tool runs once with all the files a command changed, and the checks after an edit get 45 s (`FORGE_EDIT_BUDGET`, under the hook's 60 s timeout): past that, Claude gets what was found so far, and the Stop check covers the rest.

### Files changed by Bash

Agents often edit through Bash (a heredoc, `sed -i`, `git apply`) instead of `Edit` or `Write`. Before each Bash command, `bash-snapshot.sh` records the working tree as a git tree, through a copy of the index and a private object directory, so your index and object store are never touched. After the command, `post-edit.sh` compares and runs the same checks on every file the command added or modified (up to 20), and `typecheck.sh` runs when one of them is in a type check's scope. A command that fails or is interrupted partway may already have written some files (a script that writes three files and fails on the fourth): Claude Code then fires PostToolUseFailure instead of PostToolUse, and the same two hooks run there. Formatting comes after the comparison and is not counted. A tree too large to snapshot in 5 s (`FORGE_SNAPSHOT_TIMEOUT`) is left to the Stop check, which also catches writes from background commands.
