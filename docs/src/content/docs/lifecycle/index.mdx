Forge does not add a lifecycle of its own. It plugs into Claude Code's hook events, plus `forge apply` before the session and git and CI after it. The schema below is Claude Code's lifecycle with every Forge piece attached; grey filled pieces always run, dashed ones run when a rule needs them. Every rule and pack page shows this same schema with only its own pieces lit up.

Forge acts at seven moments:

| Step | What runs | What it can do |
|---|---|---|
| [**forge apply**](./apply/) | you run `forge apply` (and `forge status`) | detects packs, writes the setup, **audits** your tool configs |
| [**Session start**](./session/#session-start) | `claude-forge hook session-start`; the rules files | **informs** Claude: the active packs' context |
| [**Tool call**](./session/#tool-call) | Claude Code permissions and sandbox; `claude-forge hook pre-tool-use` | **blocks** or **asks** before a Bash command, a read or an edit |
| [**After an edit**](./session/#after-an-edit) | `claude-forge hook post-tool-use` and its async type check | **fixes** formatting, **tells Claude** findings, **wakes Claude** on type errors |
| [**Claude stops**](./stop/) | `user-prompt-submit` snapshots the tree; `stop` checks what the turn changed | **blocks** the stop until the change passes; hands over after 3 tries |
| [**git commit**](./commit-ci/#pre-commit) | pre-commit hook → `claude-forge check --changed` | **blocks** the commit |
| [**CI**](./commit-ci/#ci) | `claude-forge check --since <base>` on a pull request, `--all` on the default branch | **blocks** the build |

## How the hooks are wired

`forge apply` writes the hook entries into `.claude/settings.json`. Each is a short `sh -c` wrapper around `claude-forge hook <event>`, one process per event. When `claude-forge` is not installed, the SessionStart entry shows you one message saying the checks are off and how to install Forge; every other entry exits 0, so Claude sees nothing.

A failure of Forge itself (a tool that could not run, an engine that did not start, a budget that ran out) is a note for you, shown by `forge status`, and never blocks Claude.

## How fast the hooks are

Every hook runs on Claude's critical path, so each has a budget it is tested against (`FORGE_BUDGETS=1 cargo test --release -p forge-cli --test hook -- --ignored budgets`): a PreToolUse guard decision within 10 ms at p99, Forge's overhead after an edit within 30 ms, a session start within 200 ms, and Forge's own overhead at Stop within 300 ms (the project's own checks are capped separately).
