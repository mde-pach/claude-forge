When Claude ends its turn, `stop.sh` runs `.forge/check.sh --changed` on the staged, unstaged and untracked files. If it fails, the stop is blocked and Claude gets the output, so it keeps working. After three blocks in a row it hands over to you.

<Spec file="08-project-hooks" describe="Stop" />

## The steps of check.sh

`check.sh` runs these steps in order and stops at the first that fails: integrity of Forge's files, applied migrations, test integrity, ast-grep `forbid` rules, format, lint and typecheck, migration checks, tests.

<Spec file="10-check" describe="steps" />

## Errors that were already there

A whole-project type check or lint run blocks only for errors in files that are part of the change. Errors already present in other files are reported as remaining and do not block; CI (`check.sh --all`) still fails on them.
