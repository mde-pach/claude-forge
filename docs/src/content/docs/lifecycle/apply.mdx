`forge apply` reads the packs, decides which are active in this repository, writes the files Forge owns, appends permission entries to `.claude/settings.json` with your consent, records everything in `.forge/forge.lock.json`, and audits your tool configs. It is idempotent.

### Monorepos

In a workspace (pnpm, npm, Yarn, Bun or uv), detection also reads each workspace package: its manifest, its dependencies and its files. A check whose tool is configured in a package rather than at the root runs in that package.

## The lock and the manifest

`.forge/forge.lock.json` records what Forge wrote, for the CLI. `.forge/manifest.sha256` lists the same hashes in `sha256sum` format for `check.sh`.

<Spec file="04-ownership" describe="the lock" />

## Your formatter and Forge's JSON

Forge formats the JSON it generates with your Biome, and hashes JSON without whitespace, so your formatter can run over Forge's files freely.

## Tool audits

For each rule with a `tool` target, Forge runs your own tool, with your own config, on the rule's examples. Forge never edits a tool config: when the audit fails it prints the snippet to add.
