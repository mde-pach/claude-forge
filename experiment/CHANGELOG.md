# Changelog (changes after the design was written)

Every change to the harness, the rules or the dataset after DESIGN.md was written is listed here, with the reason. Pilot fixes are harness fixes made before any main-run trial existed.

## Before the pilot
- 2026-10-24: target changed from 4 repos × 15 to 6 repos × 10, before any dataset build (D3). This makes generalisation across codebases more conservative.

## Pilot fixes
- **P1 (pilot1):** The parity pre-check flagged every path under `/work/.claude/` as Forge-owned. fastmcp ships its own `.claude/` directory (settings, a SessionStart hook, skills) as part of the upstream repository, present in both arms. The pre-apply check now rejects only Forge-specific markers: `.forge/`, `.claude/skills/forge-project`, `.claude/rules/forge-*`, `~/.claude/skills/forge-user`, `~/.claude/settings.json`. The post-apply check is unchanged: everything `forge apply` changes must be Forge-owned or a listed side effect.
- **P2 (pilot1):** the agent environment overrode PATH, dropping `/opt/node/bin`, so `forge apply` could not find node. PATH is now inherited from the container: the image PATH with the repo's `path_prepend`, identical in both arms. The container's full environment is now part of the parity fingerprint. On failed attempts the runner keeps logs (`_logs/`) and full pre-agent fingerprints, for diagnosis.
- **P3 (pilot1):** Forge also writes `~/.claude/forge.lock.json` (user-level lock), which is now in the Forge-owned set (`~/.claude/forge*`). Stale same-named containers from killed runs are removed before a container starts.
- **P4 (pilot1):** the Forge setup is now committed after `forge apply`, as Getting started documents. Left uncommitted, Forge saw its own files as "59 changed files" at session start. DECISIONS D9 is updated.
- **P5 (pilot1):** two harness bugs that the pilot exposed and that would have invalidated scoring. (a) `final.diff` was empty in both arms: git ran as root on a repository owned by `dev` ("dubious ownership"), and the error was swallowed. Diff collection now runs as `dev`, and a git error is an infra error. (b) A dangling `latest` symlink from Claude Code's debug log crashed log copying. Added `harness/selftest_score.py`: on every task, the reference patch must be resolved and an empty change must not. The orchestrator caps concurrent better-auth trials at 1, for disk. All pilot1 results were discarded and the pilot re-run.
- **P6 (pilot1):** stopping leftover agent processes killed the container's init (it runs as `dev`), so the container stopped before diff collection. The cleanup now spares `docker-init` and `sleep infinity`. The full reference fingerprint is stored per task, to diagnose parity mismatches.
- **P7 (pilot2):** two trials starting at once raced on the auth-token refresh temp file (an infra error, retried). The temp file is now unique per process.
- **P8 (pilot2, disk exhaustion):** the volume filled up while dataset building, pilot trials and a debug container ran at once. Rule 5 says disk failures are never results and never reject tasks. So disk or memory exhaustion (`No space left on device`, `ENOSPC`, `Cannot allocate memory`) found in an install, test-run, scoring or agent-transcript log is now an infrastructure error: the trial or candidate is retried, never scored or rejected. Candidate stages whose stored logs show it are deleted and re-processed. The scorer now also keeps its test-run log (`score_tests.log`). Afterwards dataset building runs with fewer concurrent containers.
- **P9 (pilot2):** in inngest-js, committing the Forge setup failed because the repository gitignores `.claude` (D15). The harness now commits `.forge`, and `.claude` only when it is not ignored.
- **P10 (pilot2):** a session can emit several `result` events when a background-task notification starts a new turn. The parser kept only the last one. Cost now takes the maximum `total_cost_usd` (it is cumulative), and turns are summed across results.
- **P11:** a better-auth pilot candidate was rejected as `revalidate_reference_patch_failed` because a manual cleanup removed its running container. It was reset and will be re-processed. A failed patch apply in a container that no longer runs is now infrastructure.
- **P12 (pilot2):** in inngest-js, diff collection failed because `git add` with an exclude pathspec errors on the gitignored `.claude`. It now adds everything and excludes Forge paths only in the diff. Parity errors now list the differing paths.

## Pilot summary (pilot1–pilot3, pilot-window tasks only, none in the main dataset)
5 tasks, one or more per repository (fastmcp ×2, zod, inngest-js, better-auth), 10 trials, all scored.
- Parity held in every scored trial: the pre-agent fingerprint was identical across arms and attempts.
- Forge was active in every forge-arm trial (SessionStart, PreToolUse, PostToolUse, Stop) and absent from every baseline.
- The scorer self-test passed on all 5 tasks.

Harness changes P1–P12 above. Main-run setting: 3 parallel trials, at most 2 better-auth trials at once (disk). Pilot outcomes were used only to check the harness. They were not used to tune anything that affects either arm.
- **P13 (determinism check, before the main run):** two identical preparations of pydantic-ai and logfire sometimes gave different `.venv` digests. The cause is uv's `uv_cache.json`, a timestamp cache key in the workspace package's dist-info, whose length varies. It is excluded from the fingerprint, being install bookkeeping with no behavioural effect. `harness/parity_determinism.py` prepares a task several times and diffs the fingerprints.
- **M1 (main run, during replicate 2):** the orchestrator blocked a worker on the better-auth cap, so other repos waited behind it (head-of-line blocking; 2 of 3 slots busy). Workers now take the earliest pending trial whose repository has a free slot. The orchestrator was stopped cleanly (no new trials, running ones finished) and restarted; no trial ran twice. This changes the order trials run in, never what a trial does.
- **M2 (main run, 2026-10-25):** the Forge sandbox could not start in any Run A Forge trial (D17). Container settings fixed (`systempaths=unconfined`, both arms), with a pre-agent sandbox probe and per-trial sandbox-failure counters. Run A was stopped and kept as a secondary result; Run B (`results/raw/main_b`) is the primary run.
- **M3 (2026-10-25):** added the `forge-fixed` arm (D18). It leaves the baseline and forge arms unchanged (same package, same code path); `orchestrate.py --arms` chooses arms.
