# Forge — hand-off notes

Build state of Forge against `SPECS.md` (v0.5), as of 2026-10-21 (fifth session). Read the spec first, then this file.

## Toolchain

- Bun 1.4, Node ≥ 20, uv, Claude Code ≥ 2.1.295. dash and BusyBox are optional locally (the shell matrix skips a missing shell).
- `bun install`. `jsonc-parser` is imported from `jsonc-parser/lib/esm/main.js` (its UMD entry does not bundle; its ESM build has extensionless imports, which is also why the docs run Astro on the Bun runtime).
- Build: `bun run build` → `dist/forge.js`; `scripts/postbuild.mjs` adds the shebang, chmods, and writes `schemas/*.schema.json`.
- **Spec / tests:** `bun run test` runs `tests/spec/*.test.ts` (≈ 80 s; ast-grep via `bunx`, and `11-audits` and `10-check` install Biome, TypeScript, React's types, ruff, basedpyright and (in their own venvs) Alembic and Django into a temp cache, the uv venvs on Python 3.12 (`TOOLS_PYTHON` in `tests/helpers.ts`: the config-ratchet helper needs tomllib); Squawk comes through `bunx`, so the first run needs the network). `bun run test:report` does the same and writes `test-results/<platform>.xml` (JUnit). `FORGE_UPDATE_SNAPSHOTS=1` rewrites `tests/generator/__snapshots__/`. `bun run typecheck` covers `src/`, `tests/` and `docs/src/lib/spec.ts`.
- **Pack self-test:** `bun run test:packs [packs-dir]` (`scripts/test-packs.ts`) validates every bundled pack and runs every example; `forge test` (published) checks a project's `.forge/rules` only.
- **Docs:** Astro 7 + Starlight 0.42 + React 19 in `docs/` (`bun run docs:dev`, `docs:build`; output `docs/dist/`). No Vue anywhere. `astro preview` does not start under Bun; serve `docs/dist` with any static server under `/claude-forge/` instead.
- **CI:** `.github/workflows/ci.yml` runs typecheck and `test:report` on ubuntu (with dash, BusyBox) and macOS (bash 3.2 as `/bin/sh`), uploads the JUnit files, and builds the docs with them. `docs.yml` runs after each CI run on `main`, downloads that run's results, checks out that run's commit, builds and deploys to GitHub Pages. The repository's Pages source must be "GitHub Actions" and Actions must be enabled.
- ast-grep pinned to **0.45.3**; Squawk **2.70.0**; zizmor **1.30.1**.

**Fixes from a trial on a real repository** (one commit each for 1–4):

1. Errors in unchanged files no longer block Claude: whole-project `lint`/`typecheck` runs under `--changed` and `typecheck.sh` count only errors naming a changed file; `--all` (CI) still fails on any error.
2. A `UserPromptSubmit` hook (`turn-start.sh`) records the tree hash per session; Stop runs the checks only if the turn changed the tree.
3. Audits are satisfied only when the tool fails on the example (error severity); a warning is unsatisfied with "only a warning" and the snippet.
4. `.forge/manifest.sha256` (sha256sum format) holds the owned hashes; JSON is hashed whitespace-insensitively; Forge's JSON is formatted with the project's Biome during apply, so `biome ci .` and `biome check --write .` leave integrity intact.
5. Smaller: `client-hooks` exempts custom hooks (`use…` functions); the `no-ts-ignore` fallback also matches `/* @ts-ignore */`; `typescript/strict` (which only proved `noImplicitAny`) is replaced by `no-implicit-any`, `strict-null-checks` and `strict-function-types`, one tsc example per flag.
6. Docs: getting started explains running from a clone, one `forge …` form with how it gets on PATH, `--yes`, the pre-commit hook later, and no detected pack; tests on guide pages are collapsed by default, and a pack page lists each test once (tests shared by several rules go in the pack's Specification section).

**Extension (fifth session, October 2026)**, one commit per item:

2. **Turn-scoped Stop and added lines (§8.1, §10).** `turn-start.sh` writes a snapshot (`<state>/<session>.turn/`, §8 hook state: `head`, `tree`, `dirty`, `files/`); Stop runs `check.sh --turn <snapshot>`, whose change is what differs from it (commits during the turn included). `check.sh` gained `--since <ref>` (merge base) and computes, for every mode, `changed / existing / deleted / inbase / base/ / added` (`forge_change_set` in `engine.sh`; `snapshot`, `base_file`, `added_lines` in `lib.sh`). Forbid matches (ast-grep JSON, `forge_sg_report`) and lint diagnostics (`forge_diagnostics … line`) count only on added lines; typecheck stays file-attributed. post-edit and typecheck.sh use the turn snapshot too. `forge status` prints both CI lines. **Fixes after the Docker experiment (October 2026)**, from trials on real repositories in Docker; one commit each:

1. **Formatting is not an added line (§10.1).** Check targets gained `format_stdin` (`{file}`): the formatter as a filter (`ruff format --stdin-filename {file} -`, `biome format --stdin-file-path={file}`). `forge_added_lines` (engine.sh) counts a line only when it is added against the base copy and against the base copy formatted that way, so a whole-file format after an edit does not make untouched lines Claude's (logfire: `... # pragma: no cover` got two spaces and `python/no-stub` blocked Stop). Used by post-edit.sh and `forge_change_set`; typecheck.sh sets `FORGE_PLAIN_ADDED=1` (it attributes by file). No filter, no tool, or a filter failing on the base: the plain comparison.
2. **Type check cost.** `typescript/typecheck` runs `tsc … --pretty false --incremental --tsBuildInfoFile .forge/state/tsc.tsbuildinfo` (TypeScript ≥ 4.0 for `--incremental` with `--noEmit`; checked with tsc 5.5 and 7.0; a composite project's own build info is no longer written by the check). typecheck.sh exits at once where Claude Code would run it in the foreground: Claude Code 2.1.310 backgrounds `asyncRewake` only when interactive or with streaming input (`async || asyncRewake && (!nonInteractive || hasStreamingInput)`), so under `claude -p "<prompt>"` every edit waited for tsc (44 s per edit in zod). Detection: `CLAUDE_CODE_ENTRYPOINT=sdk-cli` (set for `-p`, kept when a host presets sdk-ts/sdk-py, which always stream) and no ancestor command line with `--input-format stream-json` / `--sdk-url` (`/proc/<pid>/cmdline`, else `ps -o args= -p`; BusyBox `ps` without `-p` reads as "no streaming", i.e. skip). `FORGE_EDIT_TYPECHECK=always|never` overrides. The `.files` list of a skipped Bash call is left to `bash_cleanup`.
3. **One run per tool after an edit (§8.1).** In better-auth each Biome call cost 17–25 s, post-edit ran two per file, and Bash commands touching 2+ files hit the 60 s hook timeout. post-edit.sh now runs format, `fix_run` and lint each once with all the files in scope (`forge_file_run` / `forge_file_report` / `forge_file_fixes <list>` in engine.sh; ruff's fix codes are read per file from `--show-fixes`). `typescript/format-lint` lost its `fix_run`: `biome check --write` already applied those fixes right after, so post-edit makes one Biome call; `forge_lint_fixes` gives the "auto-fixed" line when that run changed a file beyond what `format_stdin` explains. Added lines are computed after the writes (lint diagnostics and ast-grep matches refer to the final file). The work runs under `FORGE_EDIT_BUDGET` (45 s): past it, the tool tree is killed and the findings so far are returned with a note. Formatted base copies are cached per turn in `<snapshot>/formatted/` (and `unformattable/`), so each base is formatted once per turn, by post-edit or Stop. Not measured on better-auth itself (no clone here); a Biome tool killed by the budget mid-write could in principle leave a partial file.
4. **Sandbox probe with `--proc /proc`** (Extension item 15).
5. **Workspaces (§5.1).** `readProjectFacts` (`src/packs.ts`) reads workspace packages (`workspaceDirs`: pnpm, package.json `workspaces`, uv members, else `packages/*`); `ProjectFacts` keeps the merged view plus `root` and `workspaces`. `toolPlaces` / `checkPlace` (`src/plan.ts`) decide where each check runs; `ActiveCheck.dirs` renders `c_dirs` and `forge_check_*_<n>() { forge_in_dirs …_dir <form>; }` (`engine.sh`: `forge_in_dirs`, `forge_prefix_paths`; `forge_has_tool tool@dir`; `lib.sh` `tool()` falls back to `$FORGE_WS_ROOT`). Sample `tests/generator/pnpm-workspace-app` (inngest-js layout: config only in `packages/core`). Limits in SPECS §5.1.
6. **Pre-commit with hook managers (§10.3).** `src/precommit.ts`: `hookManager`, `insertBlock` / `removeBlock` (marked block, YAML results verified by parsing: original + Forge's entry, else left to the user), lock `blocks`. `apply --yes` (or a confirmation) adds the block; `status` prints `Pre-commit: NOT INSTALLED, so commits are not checked …` and `pre_commit` in `--json`.
7. **Hooks exit 143 on SIGTERM** instead of carrying on without their temp directory.
8. **Test-run timeouts.** `vitest/run` has a 300 s timeout, and a timed-out run says so first.
9. **Failure first in block reasons.** `forge_excerpt`: Vitest/pytest summaries and failure blocks, then the rest, warnings kept; Stop: 40 lines / 6000 chars.
10. **Stop remembers a failing tree** (`<snapshot>/fail`, `fail.reason`) and repeats the reason without re-running.
11. **Failing tests are re-run at the start of the turn** (`rerun` field on test checks, `forge_test_compare`, §10.6): only new failures block, and pre-existing ones block once with their environmental errors, then are reported to the user (`systemMessage`) on a repeated Stop.

## Writing specification tests

- A file in `tests/spec/` starts with `/** @spec <number> · <title>` and a Markdown paragraph.
- Test titles are requirements, in the present tense. A `/** … */` comment right above a `test` or `describe` is rendered as explanation.
- Where a test is shown: `/** @rule <id…> */` or `/** @pack <id…> */` puts it on those rule or pack pages (tags inherit into nested tests); the per-rule examples test and the per-pack context test land on their rule and pack automatically; anything else is placed in an MDX page with `<Spec file="<slug>" describe="…" />` (or `test="…"`, or `top`). `99-internals` fails if a test is shown nowhere or a tag names an unknown rule or pack.
- Results are matched by file and **title line** (the line bun's JUnit reporter gives).
- A test that needs a tool which may be missing uses `test.if(...)`, so the site shows it as skipped rather than passed. Where the tool's own output is not what is tested, a stand-in in the sample's `.venv` (or on PATH) is better: it runs everywhere and can log its arguments for the test to assert.
- Tests sharing a sample repository must not depend on each other: in `08-project-hooks` `reset()` runs after every test (also removing ignored files such as `.forge/state/`), tools put into `.venv` are removed in a `finally` (`withStub`, `withRealBasedpyright`), and each test uses its own session ids. `bun test --randomize` should pass.
- A rule's lifecycle on the site is derived from its targets in `docs/src/lib/lifecycle.ts`, mirroring `src/plan.ts` and the hook scripts; change both together.

## How the generated checks work

- Every check target becomes `forge_check_meta_<n>` (`c_id c_stage c_tools c_when c_localdb c_timeout c_changed c_files`), `forge_scope_<n>` (literal `case` from the language extensions and `scope.files`; `!` globs exclude), `forge_when_<n>`, `forge_check_run_<n>` and, with `changed_run`, `forge_check_changed_<n>` (`{files}` → unquoted `$FORGE_FILES` with `IFS` = newline and `set -f`).
- Run strings are inserted verbatim. Project tools used in them (`ruff`, `basedpyright`, `biome`, `tsc`, `alembic`, `pytest`, `prisma`, `vitest`, `playwright`) are shell functions dispatching through `tool <name>`, so the strings run unchanged. `uv` and `bun` are checked with `command -v`.
- `--all` runs every check regardless of `when_changed` and scope (CI should verify everything); `--changed` skips a check with no in-scope changed file, or with `when_changed` and no matching changed path.
- A check whose audited tool (biome, ruff, basedpyright, tsc) is not configured in the project is not generated at all and is reported "not enforced here"; a check whose binary is merely not installed is generated and prints `skipped: <tool> not installed` at run time.
- Within a stage all checks run; check.sh stops after the first failing step or stage.

## Deliberate departures from the spec

- **ast-grep invocation.** `bunx @ast-grep/cli@X ast-grep` fails. The working form is `bunx -p @ast-grep/cli@X ast-grep`.
- **guard.sh matching.** It uses one awk pass with the same POSIX ERE instead of one `grep -Eq` per rule, to meet the 20 ms p99.
- **guard.rules format.** It has a 4th tab-separated column holding the rule description, used for `permissionDecisionReason`.
- **TypeScript parsing.** `scope.language: typescript` compiles to ast-grep `language: Tsx`, with `languageGlobs: {tsx: ["*.ts","*.mts","*.cts"]}` in sgconfig. One rule file then covers `.ts` and `.tsx`.
- **Exclusion globs.** `scope.files` entries starting with `!` become ast-grep `ignores`. They are needed for "non-test files" rules.
- **Check timeouts.** `check` targets accept an optional `timeout` (seconds), used by `pytest/run` and `vitest/run` (300 s). A run stopped by its timeout fails with `forge:<id> failed: timed out after <n>s …` as its first line.
- **check.sh is self-contained.** It inlines lib.sh so CI does not depend on `.claude/`.
- **Built-in check ids.** `forge/integrity`, `forge/applied-migration`, `forge/deleted-test`, `forge/ast-grep`, `forge/since`.
- **Suppression budget, ratchet and test integrity are pack rules, not built-ins.** The task asked for "built-in" checks with their own ids; as pack rules (a `grep` target, and check targets calling engine helpers) they get ids, examples, docs pages and `disable` for free. 1.4–1.6 share engine and renderer changes, so they are one commit.
- **Part 2 rules, differences from the task.**
  - Unused Biome suppressions: Biome 2.5.15 reports `suppressions/unused` only as a warning and has no setting to raise it, so a `tool` target can never be satisfied and `--error-on-warnings` would fail every warning. `typescript/no-unused-suppressions` is a `check` that greps `biome lint` output for that category (line-attributed like any lint check).
  - `python/no-unused-noqa` (RUF100) was added for symmetry; `BLE001` is its own rule (`no-blind-except`), because a rule's examples must trigger every tool target and S110/S112 by default flag only broad excepts.
  - `python/http-timeout`: S113 flags `requests` calls without `timeout`, but `httpx` only with `timeout=None` (httpx has a default timeout).
  - `python/no-stub` exempts `alembic/versions/**` and `migrations/**` (generated `downgrade(): pass`). Comment phrases are a separate `grep` rule per language (`no-placeholder-comment`), since a rule's examples are shared by its targets. `grep` targets gained `ignore_case`.
  - `safety/ephemeral-exec` is decided by resolution, not regex: a guard target's `check: ephemeral-exec` (guard.sh `guard_check_ephemeral_exec`, §9.2) parses the command (launcher options before the name only, compound commands, `cd`, heredocs, `sh -c`) and asks when the launcher would fetch from a registry (a package option, a version/URL spec, or a name not in `node_modules/.bin` / `.venv/bin` up to the repo root). Guard examples may be `{command, files}` fixtures. Misses: commands behind variables, `cd "$VAR"` (asks instead), global installs (asks).
  - Check commands run in a subshell (`forge_exec_check`): an `exit` in a `run` string used to end check.sh itself.
- **Docker limits.** Heredoc `RUN <<EOF` bodies are read as instructions; `ENV A="x y"` values with spaces are split; `forge_docker_nonroot` cannot resolve `USER ${VAR}` and treats it as non-root. Line-0 findings (structural) count whenever the Dockerfile changed. `config-valid` checks only a root compose file. hadolint is skipped, not trusted, when its binary does not match the upstream release.
- **Placeholders.** `fill()` replaces `@@[A-Z_]+@@` only: no digits in placeholder names (`HADOLINT_SHAS`, not `HADOLINT_SHA256`).
- **IFS in generated scripts is a newline**, so `$*` joins with newlines; helpers build word lists with loops.
- **Detecting "nobody can answer" (§9.3).** Not documented by Claude Code. Verified on 2.1.308: `claude -p` sets `CLAUDE_CODE_ENTRYPOINT=sdk-cli` and the interactive CLI `cli`; PermissionRequest fires in `-p` in default, auto and bypassPermissions modes but not in dontAsk; a PreToolUse `ask` in `-p` is denied without a PermissionRequest (so the guard reviews it itself); a PreToolUse `allow` does not override a settings `deny`. Remote and desktop sessions (`remote_*`, `claude-vscode`, …) count as having a human; `FORGE_ASK_REVIEW=always` covers unattended remote runs. An SDK host with its own approval UI should set `FORGE_ASK_REVIEW=never`. The deny `message` field on PermissionRequest is not documented; it was accepted.
- **Headless runs need a trusted workspace** for the project plugin to load (`claude plugin list` shows it skipped otherwise). Found while testing; it affects every project hook, not only the review.
- **Bash snapshots cost two `git add -A` runs per Bash command** (fast with the copied index, which keeps stat data; a 5 s guard skips huge trees). Parallel Bash calls share the snapshot object directory; it is removed when no `.tree` is pending.
- **Ratchet limits.** `vitest.config.*` / `playwright.config.*` are code, so they are only behind `ask`; coverage thresholds in them are not compared. A removed Biome rule or basedpyright `report*` key counts as loosened when it was on (the tool's default for it is not known). `extends` changes in tsconfig always count. Accepting matches the finding text anywhere in `forge.yaml`.
- **Test integrity limits.** Tests are matched by name and nesting: renaming a test reads as removed. Tests built in loops or helpers (not literal `test("name", …)` calls or `def test_*`) are not seen. Python `class` scopes include any class, so a test moved into another class reads as removed.
- **Pydantic detection.** `pydantic` is also detected via a `fastapi` dependency.
- **Audit severity (§11).** Biome is audited with `biome lint --reporter=json` on a temporary file (its stdin mode prints no lint diagnostics); ruff with `--output-format json` on stdin; basedpyright with `--outputjson`; tsc as before. A warning that fails the run (basedpyright's `failOnWarnings`, on by default) counts as enforced: the criterion is "fails the tool's CI-style run", not the label.
- **Hook commands** are `sh "${CLAUDE_PLUGIN_ROOT}/scripts/<x>.sh"`, so no executable bit is needed and a deleted `guard.sh` makes the hook fail (exit 127), which `onFailure: "block"` turns into a block.
- **Stop and the turn (§10.2).** The tree hash covers untracked files' contents, not only their names. After a pass the hash is recomputed, because `changed_run` formatters may have rewritten files. The turn-start snapshot also resets the block counter, so each prompt gets three tries. `--turn <snapshot>` is check.sh's internal mode for Stop (not in its usage line). Files over 1 MiB are not copied into the snapshot: a change to one counts as a new file (every line added). Lines are attributed by the diagnostic's start line only (tools print no end); ast-grep matches by their whole range. Diff-based "moved code" is whatever `git diff` reports as added: moving a block below a smaller one shows the smaller one as moved.
- **`--since` runs the read-only form.** CI on a pull request uses each check's `run` (whole project), then attributes diagnostics to the branch's changed files and added lines; `changed_run` (which may write, e.g. `biome check --write`) is used only by Stop and pre-commit. Built-in id `forge/since` reports a missing merge base.
- **Pre-commit hook** created by `apply` is recorded in the lock's `files` (`.git/hooks/pre-commit`), so `remove` deletes it and drift is detected; check.sh's integrity step only looks at `.forge/` and `.claude/` paths. It is only offered interactively or with `--yes`. With a hook manager, Forge's block in the manager's config is recorded in the lock's `blocks` instead (not in the manifest: the file is the user's).
- **User-level paths** are relative to the home directory (`.claude/settings.json`, `.claude/skills/forge-user/...`, `.claude/forge.lock.json`), the same shape as project paths.
- **`python/lint` `changed_run`** is `ruff check --output-format concise {files}`: ruff's default output does not fit the 20-line PostToolUse budget.
- **Receiver constraints** (data-only changes to two rules, for the two false positives the previous hand-off flagged): `pydantic/v2-api` does not flag `.json()` / `.dict()` on `r`, `res`, `resp`, `response`, `*_response`; `sqlalchemy/no-query-api` only flags `.query()` on session-like receivers (`session`, `db`, `*_session`, `s`, `sess`, `self.session`).
- **`forge test` structure checks** beyond the schema: at most one ast-grep target per rule, no ast-grep target on `language: any`, and match + no_match examples on every rule with ast-grep, guard, permission or tool targets. Guard examples also run under `bash --posix`.
- **Deprecated rules** are not enforced; `status` lists them with their replacement.
- **Errors in unchanged files (§8.1, §10.1 step 5).** A whole-project `lint`/`typecheck` run under `--changed`, and `typecheck.sh`, count only error diagnostics that name a file of the changed set (`git status`). Attribution is by path, parsed from the tools' plain output in awk (`forge_diagnostics` in `engine.sh`). Known limits: paths containing spaces are not recognised, and a tool that prints no file path (config error, crash) fails as before. **basedpyright's native baseline is deliberately not used**: `--writebaseline` writes `.basedpyright/baseline.json`, a project-owned file, and a baseline kept under `.forge/state/` would have to be regenerated whenever the tree changes outside Claude's turn; path attribution is tool-agnostic, stateless and also covers tsc and whole-project lint runs.
- **Integrity manifest (§10.1 step 1, §12).** `.forge/manifest.sha256` is in sha256sum format, but its JSON entries hold the hash of the whitespace-stripped content, so `sha256sum -c` alone verifies only the non-JSON lines; `check.sh` hashes every file itself (sha256sum, shasum or openssl). Stripping removes whitespace inside JSON strings too, so a change that only adds or removes spaces inside a string value is not detected — accepted, since no generated string's meaning depends on its spaces.
- **Formatting generated JSON.** Only Biome is used to format, and only when the project has it installed (`node_modules/.bin/biome`). A `.claude/settings.json` that already exists is never reformatted; appended entries follow its indentation (tabs or N spaces), but Biome may still prefer a different layout for the lines Forge added (e.g. collapsing a short array).
- **Guard latency (§14.3)** is measured as the guard's own cost: p99 of `guard.sh` minus p99 of an empty `sh` script, interleaved, plus a median ≤ 20 ms for the whole call. On GitHub's macOS runners, bare process start-up alone produced a p99 of 80 ms in the first CI run; locally the guard adds ~2 ms (p99 < 6 ms) to a shell start. A later macOS run measured 33 ms for the same rule set that passed before and that measures the same locally with the old and new guards, so the measurement now takes the best of up to three rounds (noise only adds time); the 20 ms bound is unchanged.

- **Roadmap rules, differences from the proposal.**
  - The bare `@ts-expect-error` check is its own rule (`typescript/ts-expect-error-reason`), not part of `no-ts-ignore`: a rule's examples are shared by all its targets, and Biome's `noTsIgnore` does not report a bare `@ts-expect-error`.
  - `typescript/no-ignore-deprecations` is a `check` (grep over tracked `tsconfig*.json`), since ast-grep rules here only cover Python and TypeScript.
  - `python/no-unscoped-ignore` uses `# pyright: ignore` examples: basedpyright reports a bare `# type: ignore` only when `enableTypeIgnoreComments` is on, while ruff's `PGH003` reports both.
  - `python/no-deprecated` adds to `python/pydantic/v2-api` instead of replacing it: the audit environment has no Pydantic, so its examples use the standard library (`datetime.utcnow()`), and v2-api still catches Pydantic v1 calls without basedpyright.
  - `typescript/no-focused-tests` sits at the `typescript` level and covers Vitest and Playwright test files; the snapshot-update guard is one rule per test pack.
  - `safety/package-add` asks only for `bun add` and `uv add`: a permission prefix cannot tell `npm install` (restore) from `npm install <pkg>`, and npm is already an ask through `typescript/bun/no-other-pm`.
- **Migration linting (§13.1).** The roadmap proposed Squawk with a list of excluded rules. On real Prisma output Squawk 2.70 also flags lock and statement timeouts, missing `IF NOT EXISTS`, `timestamp` without time zone, `serial`, `varchar`, and every index and foreign key, so an exclude list would block every migration and break with each Squawk release. The check instead fails only on an allowlist of deploy-breaking rules. Squawk gives no usable exit status (it exits 1 whenever it warns), so the helpers in `engine.sh` read its gcc output, and print lines and columns from 1 (Squawk counts from 0). Alembic SQL comes from offline mode (`alembic upgrade <down>:<rev> --sql`), which needs no database, only the project's own Alembic (and `greenlet` for the async template). CI lints only the newest migration (Prisma) or the head revision (Alembic).
- **`typescript/react/no-deprecated-types`** is limited to React's types: Biome 2.5.15 follows `@deprecated` only on direct exports. It misses Zod's `ZodSchema` (re-exported), and `useFormState` is not tagged in `@types/react-dom` (`use-action-state` covers it). Biome also resolves the tags only inside a package (a `package.json`) whose `node_modules` holds real directories; through symlinks (pnpm, or a symlinked `node_modules`) it reports nothing, and the audit then says "unsatisfied". The spec tests therefore copy React and its types into each test project instead of linking them.
- **`typescript/unchecked-index`** is audited like the strict-flag rules, so `forge status` reports it unsatisfied in projects without `noUncheckedIndexedAccess`. That is intended (the snippet says what to add); the audit never blocks.

## Open points

- **Settings formatting.** jsonc-parser reformats the arrays/objects Forge appends to (inline `["a"]` becomes multi-line). Values and comments are preserved and `remove` restores the values, but not necessarily the original layout of a pre-existing user file. A file Forge created is deleted on `remove`, so project repos come back clean.
- **ast-grep on `.ts` with the Tsx parser**: old-style `<T>value` casts in `.ts` files misparse. Rare in modern code; kept for the one-rule-file design.
- **Missing-tool noise.** check.sh prints `forge:<id> skipped: <tool> not installed` on every run, including CI. Intended (visible, never blocking), but could be reduced to once per run in CI if it proves noisy.
