### supply-chain

Detected by `**/package.json`, `**/pyproject.toml`, `**/requirements*.txt`, `**/Pipfile`, `**/setup.py` or `**/Cargo.lock`.

| Rule | Targets |
|---|---|
| `supply-chain/no-tls-disable` | `grep` forbid, any file: `strict-ssl=false`, `enableStrictSsl: false`, `NODE_TLS_REJECT_UNAUTHORIZED` / `PYTHONHTTPSVERIFY` set to `0`, `sslVerify = false`, `GIT_SSL_NO_VERIFY`, `--trusted-host`, `trusted-host =`, `allow-insecure-host`, `UV_INSECURE_HOST` |
| `supply-chain/no-tls-disable-command` | `guard` deny: `npm` / `pnpm` / `yarn config set strict-ssl false`, `--strict-ssl=false`, `NODE_TLS_REJECT_UNAUTHORIZED=0`, `PYTHONHTTPSVERIFY=0`, `GIT_SSL_NO_VERIFY=`, `PIP_TRUSTED_HOST=`, `UV_INSECURE_HOST=`, `--allow-insecure-host`, `--trusted-host`, `git -c http.sslVerify=false`, `git config … http.sslVerify false` |
| `supply-chain/insecure-download` | `guard` ask (`review`: only a local or development server): `curl -k` / `--insecure`, `wget --no-check-certificate` |
| `supply-chain/no-dependency-confusion` | `grep` forbid on requirements and constraints files, `pip.conf` / `pip.ini`, `@dockerfile`, workflows, `.gitlab-ci.yml`, shell scripts, Makefiles, `tox.ini`, `noxfile.py`, `@env-template`, `pyproject.toml`, `uv.toml`: `--extra-index-url`, `PIP_EXTRA_INDEX_URL`, an INI `extra-index-url =` (uv's TOML `extra-index-url` and `[[tool.uv.index]]` are first-index, and fine), uv `index-strategy` / `UV_INDEX_STRATEGY` / `--index-strategy` `unsafe-best-match` or `unsafe-first-match` |
| `supply-chain/no-dependency-confusion-command` | `guard` ask: `pip install … --extra-index-url`, `--index-strategy unsafe-…` |
| `supply-chain/audit-ignore-ratchet` | `grep` no-increase on `osv-scanner.toml`, `pnpm-workspace.yaml`, `package.json`, `.nsprc`, `audit-ci.json(c)`, `.trivyignore`, `.grype.yaml`, workflows, `.gitlab-ci.yml`, `Makefile`: advisory ids (`GHSA-…`, `CVE-…`, `PYSEC-…`, `RUSTSEC-…`) |
| `supply-chain/vuln-audit` | `check` lint: `forge_osv` on the changed lock files (`package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`, `bun.lock`, `uv.lock`, `poetry.lock`, `requirements*.txt`, `Pipfile.lock`, `pdm.lock`, `Cargo.lock`): pinned osv-scanner (§13.5), one backend for every ecosystem, `scan source --config <empty> --format markdown -L <lock>` on the lock and on its base copy (an empty config: `osv-scanner.toml` `[[IgnoredVulns]]` do not apply); each (package, version, advisory) present now and not in the base is a finding at line 0. Needs api.osv.dev: unreachable, `skipped`. `bun.lockb` (binary) is `skipped`. Not with `--all` |
| `supply-chain/new-npm-dep-exists` | `check` lint: `forge_helper bun new_deps.mjs $FORGE_COOLDOWN_SECONDS` (§13.4), when a `package.json` changed: each name its `dependencies`, `devDependencies`, `optionalDependencies` or `peerDependencies` gain over the base copy, with a registry spec (a range, a tag, `npm:<name>@<range>`; not `workspace:`, `file:`, `link:`, git or URL specs), is looked up on registry.npmjs.org: a name that does not exist, a deprecated version (the newest its range allows, `Bun.semver`), a package first published less than the cooldown ago are findings at the dependency's line. Names whose scope `.npmrc` maps to another registry, or all names when `.npmrc` sets another default registry, are not looked up. Registry unreachable: `skipped: registry unreachable` |
| `supply-chain/new-pypi-dep-exists` | `check` lint: `forge_helper python new_deps.py $FORGE_COOLDOWN_SECONDS`, when a `pyproject.toml` changed: the names `[project] dependencies` / `optional-dependencies`, `[dependency-groups]`, `[tool.uv] dev-dependencies` and `[tool.poetry.*dependencies]` gain are looked up on pypi.org: not found, every release yanked, or first uploaded less than the cooldown ago. `[tool.uv.sources]` pinned to an `explicit` index, Poetry sources of priority `explicit`, and path, git or URL sources are not looked up. (Split from the `new-dep-exists` proposal: one helper per ecosystem, each on its ecosystem's runtime.) |
