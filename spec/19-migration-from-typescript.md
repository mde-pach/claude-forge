## 19. Migration from the TypeScript Forge

Forge 0.5 was a TypeScript CLI (`src/`, `templates/`, bundled into `dist/forge.js` and run with Node or Bun). It generated shell, Python and JavaScript into each repository. This chapter is the only one that names that layout.

### 19.1 The old layout

Project level:

- `.forge/check.sh`, the generated checks; `.forge/ast-grep/`, `.forge/helpers/`, `.forge/manifest.sha256`, `.forge/.gitignore`, `.forge/state/`;
- `.forge/forge.lock.json`, the JSON lock;
- `.claude/skills/forge-project/`, a plugin holding the hook scripts (`guard.sh`, `post-edit.sh`, `stop.sh`, …) and `hooks/hooks.json`;
- `.claude/rules/forge-*.md`, built from each pack's `context.md`;
- a pre-commit hook or hook-manager block running `sh .forge/check.sh --changed`.

User level: `~/.claude/skills/forge-user/` and `~/.claude/forge.lock.json`.

### 19.2 What `forge apply` does with it

`apply` recognises the old layout by its lock (and `init` refuses a repository that has it), `.forge/forge.lock.json` (user level: `~/.claude/forge.lock.json`).

- The old lock is validated like the new one: it is refused as a whole when it records a file outside what forge 0.5 owned, or a settings file other than the level's (`.forge/forge.lock.json: refused: …`).
- Every file the old lock records under `.forge/` (except `.forge/rules/` and `.forge/packs/`, which are inputs) and under the old plugin is deleted when its content still has its recorded hash, plus `.forge/manifest.sha256` and `.forge/state/`, and the old lock itself. The hash forge 0.5 recorded ignored whitespace in JSON files (and also quotes, commas, semicolons and parentheses in its helper scripts); the migration computes it the same way.
- A recorded file that was modified since is listed as `<path> (generated by forge 0.5) was modified since; apply deletes it`, and `apply` stops unless `--force` is given.
- Before deleting, `apply` prints `forge: this repository has the layout of forge 0.5; moving to the new one deletes what forge generated there:`, the list, and `(kept: forge.yaml, .forge/rules/, .forge/packs/)`, then asks `forge: delete them?`. Without a terminal it needs `--yes`.
- The old lock's settings entries, blocks and rule hashes carry over as the previous state: entries the new plan still wants stay, the others are removed, and the new hook entries (§7.3) are added. The rules files and git's pre-commit hook are rewritten and owned from then on; an old hook-manager block running `sh .forge/check.sh --changed` is replaced by the new block.
- The result is the layout of §4.1 with a `forge.lock`. A second `apply` prints `forge: up to date`.
- `forge status` reports the old layout as drift: `the repository has forge 0.5's layout (forge apply moves it to the new one)`.

### 19.3 What changed for pack authors

- A pack's context is its `pack.yaml` `context:` list (§5.2); a `context.md` file is refused.
- A guard target matches a parsed command (`command:`, `words:`, `check:`, §6.2); a raw `pattern` on the whole command text is no longer accepted.
- Check commands call Forge's builtins as `forge_<name>` shell functions, which run `claude-forge internal <name>` (§6.4); the old engine's shell functions are gone.
- `forge test` (which ran a project's local rules' examples) has no Rust counterpart yet; local rules are validated when they load.

### 19.4 Behaviour changes worth knowing

- Hooks are `claude-forge hook <event>` entries in `.claude/settings.json` (§7.3), not a plugin; they need no executable scripts in the repository.
- Hook output carries findings only. Notes that forge 0.5 printed to the agent (missing tools, skipped checks, tool versions) go to `forge status` and `forge check`.
- The integrity check of generated files is gone: nothing generated lives in the repository except the rules files and the lock, which are drift-checked by `apply` and behind permission `ask`.
- Claude Code ≥ 2.1.295 is required (§2.3).

### Tests

- `crates/forge-cli/tests/apply.rs::migration_from_the_old_layout`, `::migration_keeps_a_modified_old_file_without_force`, on `crates/forge-cli/tests/fixtures/old-layout` (built by `make-old-layout.mjs` from a forge 0.5 apply of the FastAPI sample). The fixture's recorded hashes exercise the old hash rule (unchanged files are deleted, an edited one is kept without `--force`).
